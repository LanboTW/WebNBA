# WebNBA

3D 網頁籃球遊戲（Three.js + TypeScript）：5v5 完整規則，以及生涯模式。

**▶ 線上試玩：<https://lanbotw.github.io/WebNBA/>**（電腦、手機都能玩）

推上 `main` 會自動測試並部署到 GitHub Pages（`.github/workflows/pages.yml`）。

## 開發

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 規則、模擬、AI 整場測試與名單工具測試
npm run typecheck
```

## 結構

- `shared/` 遊戲模擬（固定 30Hz tick、可重現亂數）
  - `sim.ts` 每個 tick 的流程；`players.ts` 移動／投籃／灌籃／傳球／抄截／碰撞犯規；`ball.ts` 球的物理、接球、籃板、火鍋；`rules.ts` 時鐘、球權、發球、出界、違例、節次、暫停；`fouls.ts` 犯規、加罰、罰球；`bench.ts` 體力與換人；`ai.ts` 進攻與防守 AI
  - `data/roster.json` 名單（30 隊 × 8 人，可替換）
- `client/` Three.js 畫面、選單、輸入、HUD、數據表、音效
  - `showcase.ts` 首頁背景：一名隨機球員在聚光燈下運球、投籃、灌籃（用真正的模擬跑腳本操作）
- `tools/` 名單更新工具（ESPN／balldontlie → roster.json）

## 模式

首頁有四個按鈕：

- **快速模式**：選兩隊（東區／西區／自訂隊伍分組，或按「隨機對戰」），對戰電腦或觀戰。手機上分兩步：先選你的隊伍，再選對手。有生涯存檔時多一個「我的球員」分組：你的生涯球員在他目前球隊的先發陣容裡（退休後用最後一支球隊）。
- **生涯模式**：建立自己的球員（位置、身高、5 種球員類型、年齡、外觀，背景即時預覽），打 3 場選秀試訓賽（可親自上場或模擬），依表現決定選秀順位，被選中後成為球隊第 9 人，接著打例行賽（預設 29 場，可選 14／29／58／82）與季後賽（東西區各前 8 名，賽制可選）。生涯主畫面有下一場比賽、賽程、戰績表、季後賽對戰表和個人數據；自己的比賽可以親自打或用真實引擎模擬（也能一次模擬 5 場或到例行賽結束），其他球隊的比賽用快速統計模擬。比分與數據換算成 48 分鐘的 NBA 比賽顯示。上場時間由教練信任度決定：依你在隊上的總評排名（先發／第六人／輪替／替補／板凳末端），再看最近 5 場的表現評分（A+ 到 F，依每分鐘產出評分，上場很短時會趨近 C）往上或往下調。比賽可得經驗值（表現、勝利、季後賽、高難度都較多；坐板凳也有一點），在「訓練」分頁花經驗值提升各項能力，能力越高越貴，上限依球員類型。3 個存檔欄位，可登入雲端同步（見下方「雲端存檔」）。季後賽結束後進入休賽季：球季總結、年齡增長（31 歲起能力退步，35 歲可退休，40 歲強制退休）、聯盟其他球員也會成長、退步、退休，由隨機生成的新秀補上。新秀合約 3 年，到期成為自由球員，從 1–4 份報價中選一份（會顯示在該隊的預計角色）；合約期間每個休賽季可以要求交易一次。沒有薪資上限。**生涯經濟**：薪水是真的錢（萬美元），例行賽每場發一次；季末依粉絲數拿代言收入（每 10 萬粉絲約 100 萬美元）。「商店」分頁可買球鞋／服裝／配件（每件加兩項能力各 +1～+3，比賽中生效、最高 99，外觀會顯示在球員身上；頂級簽名款需 100 萬粉絲），也能參加私人訓練營（150 萬美元換 250 經驗值，每季 3 次）。粉絲隨比賽表現、贏球、季後賽和獎項成長，也會替明星賽入選加分（最多 15%）。球隊凝聚力 0–100（換隊從 30 起算，續約保留）：越高 AI 隊友越常傳球給你、隊友實力最多 +2%，75 以上教練多給一級上場時間。獎項：年度 MVP、新人王、總冠軍賽 MVP、得分／籃板／助攻／抄截／阻攻王，例行賽打到一半公布明星賽名單（只選人不打比賽）；「獎項」分頁可看本季 MVP、新人王排行和數據王（其他球員的數據依能力、上場時間與球隊估算，你的是實際打出來的）。「新聞」分頁記錄選秀、明星賽、季後賽、奪冠、得獎、生涯新高（大三元、40 分）、簽約與交易、名將退休等。退休後有生涯總結、單場生涯新高與名人堂評定（MVP、總冠軍、明星賽、數據王、新人王、生涯得分換算積分，30 分入選）；聯盟傳奇球員退休也會進名人堂。首頁背景有存檔時一半機率是你的生涯球員。
- **街頭籃球**：快速模式上方切換「快速對戰／街頭籃球」。1 對 1、2 對 2 或 3 對 3，每個位置可以挑任何球隊的任何球員（包括生涯球員），或按「隨機對戰」，紅隊是你、藍隊是對手（也能觀戰）。戶外半場、一個籃框，先到 21 分（可選 11 分）獲勝；三分線內進球 1 分、線外 2 分。換球權（防守籃板、抄截）後要先把球帶到三分線外「清球」才能得分，沒清球的進球不算。進球、出界、犯規後在弧頂重新發球（check），預設由對方發球，也可以選「進球的一方繼續持球」。沒有比賽時鐘、24 秒、罰球、暫停和換人；犯規只換發球（被犯規的投籃進了照算）。操作一名球員，L 切換，隊友由電腦控制；難度和快速對戰共用。
- **金幣**：整個帳號共用（右上角顯示）。快速對戰和街頭籃球對電腦贏 150、輸 50；生涯退休後可在退休頁把剩下的錢和經驗值結算成金幣（10 萬美元或 10 經驗值換 1 金幣，每個存檔一次）。新生涯在第一季開始前、以及之後每個休賽季，可以轉入一次金幣（每次最多 2000）：1 金幣 = 5 萬美元資金或 5 經驗值。之後 MyTeam 也會用金幣。
- **練習**：選一支球隊再選一名球員，單人、沒有時鐘，R 鍵拿回球。也可以選「我的球員」用生涯球員練習。
- **球員資料庫**：所有球隊（含自訂隊伍）的球員總評、13 項能力、身高、位置、年齡，可選全聯盟／分組／單一球隊、依位置篩選、搜尋姓名，點欄位標題排序。生涯模式的「球員」分頁看的是生涯聯盟的現況（年齡與能力會變），球季中還能切換到本季每場數據。
- **設定**：畫質、視角、官方隊徽、比賽規則（只影響快速模式）與操作說明。

多人連線已經移除（免費主機延遲太高）。

## 雲端存檔（Supabase）

生涯存檔放在 Supabase（登入＋Postgres）。不登入也能玩，存檔只在這台瀏覽器；登入後，訪客存檔會搬到雲端的空欄位。每次存檔都有版本號，另一台裝置存過比較新的進度時，會讓你選「載入雲端」或「用這台覆蓋」。

設定步驟（只要做一次）：

1. Supabase 後台 → **SQL Editor** → New query，貼上 `supabase/schema.sql` 全部內容 → Run。這會建立 `career_saves`（生涯存檔）和 `account_data`（金幣等帳號資料）資料表，以及「每人只能讀寫自己的資料」規則。腳本可以重複執行；更新版本後（例如加入金幣時）再執行一次即可。
2. **Authentication → URL Configuration**：Site URL 填 `https://lanbotw.github.io/WebNBA/`；Redirect URLs 加上 `https://lanbotw.github.io/WebNBA/` 和 `http://localhost:5173/`。
3. **Authentication → Sign In / Providers**：Email 預設已開啟（登入連結）。Google 要先到 Google Cloud Console 建立 OAuth 用戶端（網頁應用程式），授權重新導向 URI 填 Supabase 那頁顯示的 Callback URL，再把 Client ID／Secret 貼回 Supabase 的 Google 設定。Client Secret 只貼在 Supabase 後台，不放進專案。
4. 本機：`.env` 填 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY`（Project Settings → API Keys 的 publishable key，格式見 `.env.example`）。
5. GitHub Pages：repo → Settings → Secrets and variables → Actions → **Variables**，新增 `SUPABASE_URL` 和 `SUPABASE_PUBLISHABLE_KEY`（值同上），重新部署。

金鑰說明：publishable key 本來就設計成放在網頁裡，安全靠資料表的列層級安全（RLS）。**secret key（service_role）不要放進專案、.env 或 GitHub**，這個遊戲用不到它。

Supabase 內建的寄信服務每小時只能寄少量信件，玩家多了要在 Authentication → SMTP 設定自己的寄信服務。

| 灌籃（靠近籃框） | Shift＋J | RT＋X |
| 傳給指定隊友（頭上號碼） | 1–4 | |
| 傳球（進攻）／抄截（防守） | K | A／× |
| 跳：蓋火鍋、搶籃板（持球起跳＝收球） | 空白鍵 | Y／△ |

| 暫停遊戲＋數據＋換人 | Esc | |
| 切換視角（轉播／後場；生涯比賽為球員／轉播） | C | |

**手機／平板**：左半邊畫面按住拖曳是虛擬搖桿（推到底＝加速），右下三顆大按鈕的功能跟著攻守切換：

| 按鈕 | 進攻 | 防守 |
| --- | --- | --- |
| 大顆 | 投籃（按住，綠區放開；加速中靠近籃框＝灌籃） | 緊迫防守（按住） |
| 中顆 | 傳球 | 抄截 |
| 小顆 | 跳 | 蓋帽 |

直接點隊友頭上的號碼就會傳給他。左上方的小按鈕是換人、叫暫停、切換視角和選單（數據／換人）。開始比賽時會嘗試全螢幕並鎖定橫向，直放時會提示橫放。觸控筆電第一次碰螢幕時也會出現這組按鈕。

持球時隊友頭上會顯示 1–4 號，按數字鍵直接傳給他。按 K 則傳給方向鍵那一側的隊友（沒按方向就傳最近的人），橘色標亮的就是這次會接球的人。

球傳向你的時候，你的球員會自動迎上去接球（接到後立刻還你操控）；球還在飛、或剛接到球的一瞬間按傳球，會在接穩後立刻傳出（一傳一接）。

持球時可以起跳，空中也能傳球；但持球起跳就算收球，落地後只能原地轉身、傳球或投籃，不能再運球（避免二次運球）。

**視角**：轉播視角是傳統的側面視角；後場視角會站在進攻方身後、朝他們進攻的籃框看，球權轉換時鏡頭會繞過來。後場視角下方向鍵跟著畫面走（上＝往畫面深處）。主選單可以選預設視角，比賽中按 C 切換。

你控制的球員腳下有體力條（綠→黃→紅）。

**生涯比賽**：只操控自己的球員，其他隊友、換人和暫停都由電腦教練決定（不能叫暫停）。

| 動作 | 鍵盤 | 手機 |
| --- | --- | --- |
| 向持球隊友要球（自己沒球時） | K | 中顆（顯示「要球」） |
| 叫擋拆（自己持球時，最近的隊友過來掩護） | L | 小按鈕「擋拆」 |
| 換防（防守時，和防守對象離你最近的隊友交換防守對象） | L | 小按鈕「換防」 |

比賽中右上角會即時顯示你的評級（A+ 到 F，和賽後評分同一套算法）以及得分、籃板、助攻、失誤，得分、助攻、籃板、抄截、火鍋會出現綠色提示，失誤、犯規、被蓋火鍋是紅色。預設是球員視角：鏡頭在你的球員身後，看向正在被進攻的籃框（進攻時是你們要攻的籃框，防守時是你守的籃框），並微微偏向籃框或球；球權轉換時約半秒多轉過去。方向鍵以畫面為準，「上」永遠是往畫面深處，按 C 可換成轉播視角，選擇會記住。被換下場坐板凳時，比賽會以 10 倍速快轉，直到教練把你換回場上。比賽中按 Esc 可以離開，剩下的時間由電腦打完，數據照樣記錄。

選隊畫面會顯示球員總評與球隊評分（先發五人總評平均）。總評採 2K 式尺度：依位置加權各項能力，再加重球員最強的五項，最後用固定曲線換算（以 2026-27 名單校準：聯盟最佳 98、前十約 93、中位數約 76、板凳末端約 62；歷屆 MVP 大約在 97–99）。比賽模擬直接使用 13 項能力值，總評只影響顯示與排序。生涯球員從總評 65 起步，每種類型都能練到 97 以上（約 6–8 季）。

靠近籃框（2.6 公尺內）按住 Shift 出手會灌籃；只有身高加彈跳摸得到籃框的球員能灌，其他人會改成上籃。灌進後會掛在籃框上一下。

按住加強防守時，球員會自動貼到持球者（或你盯的人）與籃框之間並跟著滑步，方向鍵可微調；對手投籃較難進、抄截機率提高，持球者移動變慢。控制圈會變紅色。代價是比較耗體力，也比較容易被吹犯規。

防守者要站定或滑步才有完整的干擾效果：用跑的（超過每秒 3 公尺）會漸漸變差，全速奔跑時對投籃的干擾和抄截機率只剩六成。旁邊 2.5 公尺內沒有對手時，球員不會擺出張手的防守姿勢。

## 規則

主選單可以分別關掉三組規則：

- **犯規與罰球**：投籃犯規（進算加罰，沒進罰 2 或 3 球）、打手、阻擋與進攻犯規（防守者站定、面向持球者、不在合理衝撞區內才算撞人）、加強防守時的非法接觸。每節第 5 次團隊犯規起加罰（延長賽第 4 次）；每節最後 2 分鐘（依節長等比例縮短）第 2 次犯規也加罰。個人 6 犯離場。罰球用同一個投籃計量條，最後一罰出手後其他人才能搶位置。
- **違例**：進攻 3 秒、防守 3 秒（技術犯規，罰 1 球後進攻方發球）、8 秒過半場、回場、5 秒發球。
- **體力與換人**：上場會掉體力（衝刺、加強防守掉更快），體力低會跑得慢、投得差、跳得低；替補在板凳上恢復。死球時會自動換下太累或犯滿的球員，電腦教練也會把休息好的主力換回來。你也可以在 Esc 或暫停畫面點場上球員、再點替補，下次死球就會換。

每隊每場 5 次暫停（延長賽各加 1 次），每次最多 30 秒。第 4 節與延長賽最後 2 分鐘，持球方喊暫停後改在前場發球。對手打出 8 分以上的攻勢時，電腦會喊暫停。

走步與二次運球不是吹判，而是做不出來：持球起跳落地後，系統只允許轉身、傳球或投籃。

## 名單

`shared/data/roster.json` 以 2025-26 開季名單為底，每位球員格式為
`[名字, 背號, 身高(m), 位置, [能力值…], {外觀}]`，能力值順序見檔案內的 `ratingKeys`，外觀見下方「球員外觀」。

### 手動更新名單

名單由你自己決定什麼時候更新，兩種方式都可以：

- **直接改檔案**：編輯 `shared/data/roster.json`（交易就把那一行搬到新球隊），跑 `npm test` 確認沒問題後 commit、push。
- **用更新工具**抓最新球隊，預設來源是 ESPN 的公開名單，不需要金鑰，幾秒鐘就跑完：

```bash
npm run roster:update                              # 顯示差異，確認後寫入並自動跑測試
npm run roster:update -- --yes                     # 不詢問直接寫入
npm run roster:update -- --source balldontlie      # 改用備用來源 balldontlie（需要 .env 裡的金鑰）
npm run roster:update -- --relook                  # 重新分析所有人的大頭照（換髮型、留鬍子時）
```

（Windows PowerShell 請打 `npm.cmd`。）

工具的行為：

- 能力值是手調的，工具不會改；它只會把球員移到新球隊、更新背號，並處理名單進出：
  - **ESPN（預設）**：讀 30 隊的現役名單。離開聯盟的球員會移除，新球員會用依位置的預設能力值補進來，球季標籤（例如 2026-27）也會跟著更新。
  - **balldontlie 備用**：免費方案只能讀全部歷史球員，所以只追蹤現有球員轉隊（每分鐘限 5 次請求，跑一次約 10–15 分鐘）；ALL-STAR 以上方案能讀現役名單，效果和 ESPN 相同。
- 想調整能力值、背號、位置或指定球隊，寫在 `shared/data/overrides.json`，每次更新都會套用。
- 每隊保持 5–10 人；表現比先發差的新人放板凳，比較強的會頂替最弱的先發。
- 寫入後會自動跑測試，失敗就還原名單。測試使用 `shared/test/fixture-roster.json` 這份固定副本，所以真實的交易不會讓測試失敗。
- 確認後 commit 並 push，GitHub Pages 會自動重新部署。

### 金鑰安全

- 只有備用來源 balldontlie 需要金鑰，預設的 ESPN 不需要。
- `BALLDONTLIE_API_KEY` 只放在本機專案根目錄的 `.env`（格式見 `.env.example`）。`.env` 與任何 `.env.*` 都在 `.gitignore` 裡，只有 `.env.example` 例外，所以金鑰不會被 commit。
- 這把金鑰只有你電腦上的更新工具會用，網頁不需要它。
- 變數名稱沒有 `VITE_` 前綴，前端建置永遠不會把它打包進網頁。
- 工具輸出的所有訊息都會遮蔽金鑰，錯誤訊息只有路徑和狀態碼，不含請求標頭。

### 自訂隊伍（歷史、台灣、彩蛋隊）

自訂隊伍寫在 `shared/data/custom-teams.json`，名單更新工具永遠不會碰這個檔案。選單會把它們依 `group` 分組，排在 NBA 30 隊後面：

```json
{
  "ratingKeys": ["speed", "jump", "close", "mid", "three", "ft", "handle", "pass", "steal", "block", "defense", "rebound", "stamina"],
  "teams": [
    {
      "group": "歷史隊伍", "abbr": "CHI96", "name": "1995-96 Chicago Bulls", "primary": "#CE1141", "secondary": "#000000",
      "players": [
        ["Ron Harper", 9, 1.98, "PG", [75, 70, 74, 70, 68, 70, 74, 74, 75, 45, 82, 50, 80]],
        ["...", 23, 1.98, "SG", [/* 13 個能力值 */]]
      ]
    }
  ]
}
```

| 欄位 | 規則 |
| --- | --- |
| `group` | 選單分組標題，例如「歷史隊伍」「台灣」「彩蛋隊伍」，沒寫就歸到「自訂隊伍」 |
| `abbr` | 2–5 個大寫英文或數字，不能和其他隊重複；會顯示在記分板和中場地板 |
| `name` | 隊名，可以用中文 |
| `primary` / `secondary` | `#RRGGBB`；主隊時球場和觀眾席會用主色 |
| `logo` | 選填。隊徽圖片路徑，相對於 `client/public/logos/`，例如 `"taiwan/tpe.png"`；PNG／WebP／SVG、300KB 以內、建議正方形透明背景。沒寫就只顯示縮寫 |
| `players` | 5–10 人、前 5 人先發；格式同 `roster.json`；名字可以用中文；身高 1.4–2.6 公尺 |

改完執行 `npm test`，裡面有一項會檢查這個檔案（縮寫重複、顏色格式、人數、能力值範圍、隊徽檔案是否存在和大小都會擋下來），通過後 commit、push 即可。新增隊伍也會改變連線版本，開著舊網頁的人會被提醒重新整理。

### 球員生日（生涯模式年齡）

`npm run ages:update` 會從 ESPN 公開 API（不需金鑰）抓所有現役球員的生日，寫到 `shared/data/birthdays.json`（不會動到 roster.json）。生涯模式用它算聯盟球員的年齡；沒有生日資料的球員會用名字算出固定的估計年齡。

### 球員外觀

每位球員最後一欄是外觀，例如：

```json
{"skin": 3, "hair": "short", "beard": "none", "headband": false, "sleeve": "none", "kneepad": false, "shoe": "white", "socks": "low"}
```

| 欄位 | 可用的值 |
| --- | --- |
| `skin` | 膚色 `1`（最淺）～`6`（最深），或 `#RRGGBB` |
| `hair` | `bald` 光頭、`buzz` 平頭、`short` 短髮、`afro` 爆炸頭、`twists` 小辮、`dreads` 髒辮、`long` 長髮、`mohawk` 莫霍克 |
| `hairColor` | 選填，`#RRGGBB`；沒寫是黑色 |
| `beard` | `none`、`stubble` 鬍渣、`full` 落腮鬍 |
| `headband` / `kneepad` | 頭帶、護膝：`true` / `false` |
| `sleeve` | 袖套：`none`、`left`、`right`、`both` |
| `shoe` | 球鞋：`white`、`black`、`team`（隊色） |
| `socks` | `low` 短襪、`high` 長襪 |

- **NBA 球員**：更新工具會讀 ESPN 大頭照，自動判斷膚色、髮型和鬍子（照片只在記憶體裡分析，不會存檔）；配件第一次隨機產生。之後交易會跟著球員走，更新不會改掉已經有的外觀；加 `--relook` 才會重新分析。自動判斷不一定準，可以直接改 `roster.json`。
- **想永久指定某人的外觀**：寫在 `overrides.json`，例如 `"Stephen Curry": { "look": { "beard": "full" } }`，只寫要改的欄位，遊戲會直接套用，不用跑更新。
- **自訂隊伍**：在 `custom-teams.json` 新增球員後執行下面指令，沒有外觀的人會補上預設值（膚色 3、短髮、無鬍子）和隨機配件，已經寫好的不會動，其他內容也不會被重新排版：

```bash
npm run looks:fill
```

### 隊徽

隊徽會顯示在選單與大廳的隊伍卡片、記分板和主隊的中場地板。

- **NBA 30 隊**：存在 `client/public/logos/nba/縮寫.png`，依縮寫自動對應。圖檔來自 ESPN，球隊換隊徽或改名時執行一次：

```bash
npm run logos:update
```

- **自訂隊伍**：把圖檔放進 `client/public/logos/`（可以自己建子資料夾），再在 `custom-teams.json` 寫 `logo` 欄位，請使用你有權使用的圖片。
- 選單的「顯示官方隊徽」可以關掉 NBA 隊徽（自訂隊伍的圖不受影響），關掉或圖檔讀不到時改顯示縮寫。
- NBA 隊徽是 NBA 與各球隊的註冊商標；本專案是非官方粉絲作品，如被要求移除，把 `main.ts` 裡 `officialLogos` 的預設值改成 `'0'` 即可全部隱藏。
